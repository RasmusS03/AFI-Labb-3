Av Keni Ren

 

Objective

By completing this lab, you will:

  • Gain an understanding of WebSockets and how SignalR facilitates real-time communication.
  • Implement a structured chat application that allows dynamic user interactions.
  • Learn how to manage and deploy a multi-user chat system.
  • Optionally extend the project with additional WebSocket and SignalR functionalities. (Plus-level tasks)

 

Theory 

Before we start coding, let’s get our brains warmed up!

Instead of providing the textbook, we want you to find some good sources on your own where you can read up on :

  • What is socket communication, and why do we need it?
  • What is WebSocket, and how does it work?
  • What is SignalR, and how does it make WebSockets easier to use?

Implementation

You will develop a real-time chat application using SignalR, ASP.NET Core, and React. The application is for facilitating course discussions and lab supervision and allows students and teachers to communicate effectively.

The lab is structured into two levels:

  • Basic Level: Implement a fully functional real-time chat system.

  • Plus Level: Enhance the chat system with advanced features such as user roles, topic categorization, and additional real-time interactions.

 

Note: Storing and retrieving past messages (e.g., old announcements or chat history) is not required for this lab. The focus is on real-time communication using WebSockets and SignalR, a database is not required for the basic level task. However, it's a great idea and would fit perfectly as a Plus-level feature if you'd like to explore it further.

 

Basic Level (Required Tasks)

At this level, you will build a foundational chat application with real-time message exchange between multiple users.

 

Task 1: Project Setup and Dependency Management

  • Set up a new ASP.NET Core Web API backend project and a React frontend.
  • Install the necessary libraries to support real-time communication with SignalR.
  • Configure a basic project structure that will be used to build the chat system.

 

Task 2: Implementing Real-Time Communication

  • Develop a SignalR Hub in the backend that allows users to send and receive messages in real-time.
  • Ensure that messages are broadcast to all connected users.
  • Handle different connection states, ensuring that users join and leave sessions properly.

 

Task 3: Building the Chat Interface

  • Create a simple user interface in React that allows users to input messages and view received messages dynamically.
  • Ensure that messages are updated without requiring a page refresh.

 

Task 4: Managing Basic Chat Functionality

  • Implement user identification, so messages display who sent them.
  • Validate user inputs to prevent empty messages.
  • Limit the number of messages displayed to optimize performance.

 

Task 5: Implement Basic Role Distinction (Students vs. Teachers)

  • Allow students and teachers to join the chat with predefined roles.
  • Students can participate in general discussions and send messages as usual.
  • Teachers can post announcements in a separate, dedicated announcement channel.
  • Ensure that only teachers can send messages in the announcement channel, while students can only view them.

 

Task 6: Testing the Real-Time Chat Application

  • Run both the backend and frontend.
  • Open multiple instances of the application and verify that messages appear instantly across all instances.
  • Debug and resolve any connection issues that may arise.

 

Plus level

These additional tasks provide more complexity and functionality for students looking to deepen their understanding of real-time applications.

You can choose 2 of these tasks to achieve the plus level:

 

P-1: Implement User Roles and Permissions

  • Expand on the basic role system by giving teachers administrative privileges.
  • Allow teachers to edit/delete inappropriate messages.
  • Enable teachers to pin important messages for better visibility.

 

P-2: Categorized Discussions

  • Implement a topic-based discussion system in which users can select different categories for their messages (e.g., Assignments, General Questions, and Supervision).
  • Allow users to filter messages by topic, ensuring better organization within the chat.

 

P-3: User Presence Management

  • Track when users join or leave the chat.
  • Display an online user list that updates dynamically as users connect and disconnect.

 

P-4: Private Messaging

  • Introduce a private messaging feature, allowing users to send direct messages to specific individuals.
  • Ensure that private conversations are visible only to the sender and receiver.

 

P-5: Storing and Retrieving Chat History

  • Implement a database system to store past chat messages.
  • Load previous messages when users join a chat session.

 

P-6: Implementing a Typing Indicator

  • Notify users when someone is typing in a chat session.
  • Display a small notification that disappears once the message is sent.

 

How to Present Your Work

For this lab, you will NOT hand in a written report. Instead, your assignment will be presented as a short ( around 15mins) recorded mini-lecture — imagine you’re making a YouTube tutorial for fellow students!

What to include in your recording:

  • Theory Summary
    Start your video by presenting what you’ve learned from the Theory section:
    • What is socket communication and why is it needed?
    • What is WebSocket and how does it work?
    • What is SignalR and how does it simplify using WebSockets?
    • Use your own words and sources, and explain like you’re teaching someone with the same background as you — someone who hasn’t done the lab yet.
  • Tutorial Process
    Walk us through the tutorial you followed. What did you do step-by-step to get the basic chat app running?
  • Your Customizations
    Finally, explain how you modified or extended the tutorial to meet the specific tasks in our lab (basic and/or plus level). What did you change, add, or troubleshoot?
  • Optional: If you found other useful tutorials or resources along the way — mention them in your video or show them briefly!

How to Submit

  • Upload your code to GitHub. Make sure your GitHub repo is set to public, so the teacher can access it without any permissions. .
  • Submit the recording.
  • Link your GitHub in the comment area.

 

That's it!

Make sure your video is short, clear, and focused (around 15 minutes). Don't worry about fancy editing — just make sure we can hear and see what you're explaining (screen recordings with voice-over are totally fine).
